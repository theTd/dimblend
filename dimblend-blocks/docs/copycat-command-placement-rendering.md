# 伪装方块命令放置后的首次渲染

## 症状与复现

这是底盘功能之前已经存在的问题：用 `/setblock` 或 `Level.setBlock` 放置非默认朝向的伪装板、半砖、梁时，碰撞和选中正常，世界内可能不显示；附近方块发生状态更新或重进世界后恢复。底部伪装板、下半砖、竖梁通常不受影响。

真实客户端复现矩阵共51种状态：Create普通板、创造板及洁净板的6种朝向；Copycats+普通半砖、创造半砖、洁净半砖的3轴×3种半砖类型；普通梁、创造梁的3轴。基线截图显示非默认样式缺失；相同时刻读取BE与ModelDataManager的材质数据、按世界状态生成的面都有效，附近放置石头后网格恢复。

## 修复位置与边界

- 沿用Create/Copycats+的模型、材质与隐藏封装；不替换模型或改变方块状态。
- 仅客户端，在Create `CopycatBlockEntity.onLoad` 和Copycats+的 `CCCopycatBlockEntity.onLoad`、`MultiStateCopycatBlockEntity.onLoad` 尾部登记一次重绘。
- 入队前排除空世界、逻辑服务端和非当前客户端世界；避免单机集成服务端或虚拟展示关卡访问客户端队列。下一个客户端tick刷新模型数据并通过原有 `sendBlockUpdated(..., UPDATE_KNOWN_SHAPE)` 请求网格重建。移除、替换或离开世界的BE不会被重绘。
- 两个mixin均只在client配置中声明，目标模组缺席时由既有plugin跳过。处理器为private实例方法，匹配数用require/allow固定。
- 不给无ticker的伪装BE添加持续tick，不触发服务端邻居更新或Sable方块状态/质量更新。

## 本地验证方式

临时客户端QA助手只放在构建目录，不进入组件jar：在独立测试存档里通过服务端 `setBlock(..., UPDATE_CLIENTS)` 放置上述51种状态，等待同步，记录方块状态、BE状态、直接与缓存材质模型的面数并截图；随后触发邻居更新再次采样作对照。测试使用实际整合包客户端，覆盖普通与创造变体，不依赖手动补一次邻居更新作为修复。

2026-10-18 最终客户端复测：51种状态在邻居更新前全部显示；检查真实集成服务端BE不会入队；创造板/半砖隐藏及恢复、板/半砖/梁使用石头与玻璃材质都能产出模型，测试后方块状态和BE NBT保持原样。临时QA源码、日志和前后截图保存在工作区构建目录，组件jar不含QA助手。
