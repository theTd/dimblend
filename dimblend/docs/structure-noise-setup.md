# 旋转维度结构生成：共享密度函数映射

离开铁路走廊后，新区块开始尝试生成结构。拼图结构会反复查询基础地形高度，每次查询都创建 `NoiseChunk`，将噪声函数图映射成当前列的插值器和缓存。原先对同一共享分支反复执行 `mapAll`，产生大量临时对象，也反复计算复杂记录的哈希。

`RotatingChunkGenerator.createStructures` 用 `StructureNoiseSetup.run` 包住委托生成器的结构生成。仅在这个线程作用域中，`NoiseChunk` 构造器的两轮映射建立临时表：

- `NoiseRouter.mapAll` 映射噪声路由器。
- `DensityFunction.mapAll` 映射方块填充用的最终密度函数。

每张表按原始节点的对象身份记录本轮映射结果，并核对访问器身份。`HolderHolder` 的共享引用，以及 `Ap2`、`MulOrAdd`、`RangeChoice` 的共享算术分支，在同一轮中只遍历一次。最终 `NoiseChunk.wrapped` 仍使用原有的 `HashMap`，保持原有相等性和缓存共享行为。

表在每轮映射的 `finally` 中移除；嵌套调用恢复上一张表。列之间、区块之间、工作线程之间均不复用包含可变插值状态的结果。普通地形生成和其他映射访问器走原实现。没有高度结果的长期缓存，也没有修改结构概率、结构模板、噪声公式或存档格式。

开发排查时可加 JVM 参数 `-Ddimblend.disableStructureNoiseOptimization=true`，关闭结构生成作用域中的映射复用。

## 验证记录：2026-10-19

完整 NeoForge 21.1.249 客户端、201 个原包模组及原存档副本中，交替运行原路径和优化路径：

- 14 个目标区块，每个做两轮，28 对完整结构 NBT 全部一致。
- 9 个代表性纬度/维度类型的 3,618 项高度与逐方块地形列检查一致；177 项源函数哈希检查一致。
- 同一进程、同一构建的预热轮合计：未进入优化作用域的基线 29.131 秒、10,122,370,784 字节线程分配；优化路径 10.259 秒、1,759,229,088 字节。耗时减少约 65%，分配减少约 83%。这不是与未修改整合包进行的受控 FPS 对比，基线也包含新增 mixin 的透传路径。
- 主要收益来自图较大的主世界结构；较轻的特殊纬度样本基本持平，个别样本有数毫秒开销。
- 新地形探索沿 x=3072 从 z=0 到 z=2048，分段等待区块到达。进入 z=256 以后的 167 个帧统计窗口中，最大单帧 741.56 ms，未记录到超过 1 秒的帧；仍有可感知的生成卡顿，不能据此宣称所有探索卡顿均已消除。
- 探索 JFR 中渲染线程有一次 216.27 ms 的分配等待。QA 副本关闭了原先开启的天空时间追踪，原客户端的该配置未修改。
- `:dimblend:test` 全部 141 条通过；已实际触发所有新增 mixin 的结构生成与高度查询路径。

计时和分配来自游戏内线程的 `System.nanoTime` 与 `ThreadMXBean`，不把首次模板加载、JIT 预热或分析工具自身造成的长停顿当成稳态收益。比较覆盖同一种子和本机模组组合；其他种子和第三方密度函数仍需正常兼容性回归。
