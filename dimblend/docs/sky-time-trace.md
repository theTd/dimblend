# 偶发天空突变诊断

用户反馈原地等待也可能在天亮或天黑附近看到天空突变，目前未确认太阳、地面亮度是否同时变化，未稳定复现。现阶段不改变时间同步、纬度锁时或天空渲染规则。

客户端更新包含本功能的 dimblend 和 dimblend-experience jar，在 `/dbx` 调参主面板开启“天空时间诊断（仅本机）”。默认关闭，立即生效，并保存到本机 `config/dimblend-client.toml` 的 `skyTimeTrace`；关闭或重置立即停止记录。此项不发送服务器调参请求，不影响其他玩家，也不占用服务器调参快照的32位掩码。

不再读取 JVM 系统属性。服务端无需更新或启用本功能。打开面板仍沿用现有 `/dbx` 权限要求；本机诊断行本身不受服务端配置只读状态限制。观察到突变时记下大约的现实时间，并保留当次 `logs/latest.log`。日志中搜索 `[sky-time]`：

- `neoforge-time-payload`：NeoForge 自定义时间载荷的构造/解码参数，包含时钟、游戏规则、昼夜速率与小数累积；此项不表示载荷已经应用。集成服务端可能在 Server thread 和网络线程分别记录同一载荷，需结合线程名及后续写入/帧记录判断。
- `time-packet`：原版时间包处理前后的可见时间；保留原版兼容路径，NeoForge 通常使用上一项的载荷。
- `day-time-write`：幅度至少 4 tick 的客户端时间写入及调用路径，可能包含合法快速昼夜推进；锁时期间的底层写入不生成此项，避免把不可见的世界时钟写入当成天空跳变。
- `clock-step`：两帧之间可见时间与 `tickTime` 内实际自然推进量不符，偏差至少 4 tick；采用实际写入增量，兼容 NeoForge 小数累积和自定义昼夜速率。可能是合法睡觉、指令或纬度切换，需结合其他记录判断。
- `time-lock`、`sky-overlay`：纬度锁时目标或天空类型发生变化。
- `sample`：每 5 秒记录维度、玩家和相机位置、时间、锁时、纬度、天空类型、区块加载、暂停、帧率和雨雷强度。

诊断不会平滑或屏蔽时间包，不改变太阳位置、昼夜长度或任何服务端规则。它用于区分时间校正和天空切换，不能单凭某一条日志认定根因。当前不主动读取或修改第三方光影内部状态。
