# z256 提示条需求文档

> 2026-09-30 用户口径重写（计数器方案，对应用户 scoreboard 描述）：
> 进度条与扣血共用同一个“已满次数”计数，方向判定（回程瞬时归零 / 回程锁存）全部作废。

## 1. 目标

用一个进度条替代之前的 bossbar，显示玩家朝“下一次扣上限”的进度。条上数字显示 `z` 的绝对值。

## 2. 术语

- `|z|`：玩家坐标 `z` 的绝对值。
- 层级 `n`：进度条已满（到 100%）的次数，与远行诅咒（A3/A4）共用同一计数，服务端持久化并同步给客户端。

## 3. 显示规则

常驻显示：生存/冒险/创造均显示，旁观隐藏。创造下血量/盔甲层不渲染，经 HOTBAR 回退绘制，落点与生存一致。

### 3.1 进度

- 进度 = `( |z| − 256 × n ) / 256`；**为负显示 `0%`**。
- 与走向无关：同一位置、同一层级，去程回程显示一致。

### 3.2 层级变化（即用户 scoreboard 循环）

- 进度到 `100%`（`|z| ≥ 256 × (n+1)`）→ `n + 1`，生命上限再 `-25%`（×0.75 乘算），之后按新 `n` 重新算进度。
  一次跨多段（传送）时补齐层级。
- 回到 `|z| ≤ 128` → `n` 清零，重新开始（生命上限完全恢复）。
- 其余情况 `n` 不变（只增不减）。
- 层级计数在旋转维度内常开；`depthCurse` 开关只管扣上限与粒子，关闭后进度条仍按层级显示。
- 恰到 100% 的瞬间层级即 +1，满条只闪现一下随即回 `0%`（用户确认）。

### 3.3 颜色

- 边界按左闭右开：`[0,60%)` 绿、`[60%,80%)` 黄、`[80%,100%]` 红。

### 3.4 数字

- 只显示 `|z|` 取整，不加前缀。
- `|z| ≤ 16` 时只画进度条、不画数字。

### 3.5 新旧替代

- 本条替代之前的 bossbar。旧“只在边界前 32 格显示”、`|z| % 256` 段内进度、回程瞬时归零、回程锁存口径均作废。

## 4. 示例

| 经过 | 位置 | n | 条 |
|---|---|---|---|
| 出发 | `\|z\|=16` | 0 | `6.25%` 绿，不显示数字 |
| 前进 | `\|z\|=200` | 0 | `≈78%` 黄 |
| 未过 256 就回头 | `\|z\|=200` | 0 | `≈78%` 黄（与走向无关） |
| 前进到 256 | `\|z\|=256` | 0→1 | 满条后立即 `0%`，上限 20→15 |
| 前进 | `\|z\|=300` | 1 | `≈17%` 绿 |
| 前进到 512 | `\|z\|=512` | 1→2 | `0%`，上限 15→11.25 |
| 前进 | `\|z\|=600` | 2 | `≈34%` 绿 |
| 回头 | `\|z\|=400` | 2 | `0%`（400−512 为负） |
| 回头 | `\|z\|=300` / `200` | 2 | `0%` |
| 再前进越过 512 | `\|z\|=550` | 2 | `≈15%` 绿 |
| 回到 128 以内 | `\|z\|=128` | 2→0 | `50%`（128/256），上限恢复 20 |

## 5. 实现要点

- 层级存服务端玩家附件 `far_curse_tier`（`DepthCurse` 维护），经 `FarCurseTierPayload` 下发：层级变化、登录、重生、切维度时发送；客户端断线复位。
- 客户端 `|z| ≤ 128` 直接按 `n=0` 计（与服务端清零同口径，不等同步包）；越过下一边界而 +1 尚未同步到的几 tick 钳为满条。
- 256 / 128 常数取自 `DepthCurse`，单一来源。
